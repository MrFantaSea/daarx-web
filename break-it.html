Security

Check the claims.
Then check the code.

Private tests are useful evidence. They do not replace independent review, a public network campaign or scrutiny of the system as a whole.

01

The review has to reach
the whole system.

Reviewed dependencies do not automatically make their composition safe.

Cryptography.

Proof systems, amount commitments, signatures and their dependencies need scrutiny of assumptions, implementation and integration.

Consensus and the network.

Transaction rules, mining commitments, history, forks, cross-chain boundaries and fault behavior must agree in the actual release.

The person holding the key.

Wallet creation, signing, backups, interrupted sends, recovery and device behavior are part of the security boundary.

02 / PUBLIC TESTING

A network campaign
has a different job.

The public Testnet is intended to exercise software and operations beyond controlled private tests. Supported participation, reset rules, report scope and recovery instructions will be published with the release.

Public entry is not open yet. This page does not authorize testing third-party services, commercial infrastructure or systems outside a published scope.

03 / SECURITY PROGRAM

The public program
hasn’t opened.

A public program needs confirmed funding, official rules, clear scope, a reporting channel, safe-harbor terms, response expectations and an award process. Those are not published as an active offer today.

No amount, reward, credit or invitation is promised by this page. A hardware-interest submission does not enter a security program.

04 / CONTACT

Questions are welcome.
